# Backlog Refinement (Grooming)

Goal: make tickets clear and estimable before planning.

## Terms
| Term | Meaning |
|------|---------|
| User story | "As a [user], I want [x], so that [y]" |
| Acceptance criteria (AC) | Conditions that define "done" for the story |
| Story points | Relative effort estimate (1, 2, 3, 5, 8, 13) |
| Spike | Time-boxed research task |
| Definition of Ready (DoR) | Ticket has enough info to start |
| Split | Break a large story into smaller ones |

## Phrases
- "What's the expected behavior when...?"
- "Are there any designs for this?"
- "Can we add acceptance criteria for the error state?"
- "This feels like an 8 — can we split it?"
- "I think we need a spike before estimating."
- "Is this in scope for the MVP?"
- "Do we have any dependency on another team here?"
