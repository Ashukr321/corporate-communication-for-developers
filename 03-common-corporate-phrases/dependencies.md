# Dependencies

A **dependency** is something your work needs from someone or something else — an API, a design, access, another ticket, a library.

## Phrases
- "This ticket has a dependency on the auth team."
- "We're dependent on the design team for final mocks."
- "Can we identify dependencies during planning?"
- "Once the API is ready, I can complete the integration in a day."
- "Is there a way to decouple this so we're not waiting?"

## Types
| Type | Example |
|------|---------|
| Team dependency | Backend API not ready |
| Technical dependency | Library upgrade needed first |
| External dependency | Third-party vendor / client approval |
| Ticket dependency | JIRA-120 must be done before JIRA-121 |

## Managing it
1. Call it out early (in planning).
2. Agree on a date with the other team.
3. Use mocks / contracts to work in parallel.
4. Follow up before the date, not after.
