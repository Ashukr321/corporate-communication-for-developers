# Development Terminology

| Term | Meaning | How it's used |
|------|---------|---------------|
| Requirement | What the feature must do | "Can we clarify the requirement for guest checkout?" |
| Scope | Boundaries of the work — what's in and out | "Dark mode is out of scope for this sprint." |
| Implementation | The actual code that delivers the feature | "The implementation is complete; PR is up." |
| Approach | The chosen way to solve a problem | "I'd like to align on the approach before starting." |
| Feasibility | Whether something can be done (time, tech, cost) | "Let me check the feasibility of real-time sync." |
| Dependency | Something your work relies on | "This has a dependency on the auth team's API." |
| Constraint | A limit you must work within | "We have a constraint — no new third-party libraries." |
| Edge case | Unusual input or situation | "What about the edge case where the cart is empty?" |
| Technical debt | Shortcuts that cost more later | "This adds tech debt; let's create a ticket to clean it up." |
| Refactoring | Restructuring code without changing behavior | "I'll refactor the service before adding the new endpoint." |
| Regression | Something that used to work is now broken | "The last release caused a regression in search." |
| Optimization | Making it faster/cheaper/lighter | "This query needs optimization — it takes 4s." |
| Root cause | The real underlying reason for a problem | "The root cause was a missing DB index." |
| Impact | Who/what is affected and how much | "The impact is limited to Android users on v3.2." |
| Workaround | Temporary way around a problem | "As a workaround, users can refresh the page." |
| Compatibility | Works with other versions/systems/browsers | "Is this backward compatible with the v1 API?" |
