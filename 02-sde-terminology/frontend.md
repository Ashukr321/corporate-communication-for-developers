# Frontend Terminology

| Term | Meaning |
|------|---------|
| Component | Reusable UI building block |
| Props / State | Inputs to a component / its internal data |
| Rendering (CSR / SSR / SSG) | Client-side / server-side / static generation of HTML |
| Hydration | Making server-rendered HTML interactive on the client |
| Responsive | Works across screen sizes |
| Accessibility (a11y) | Usable by people with disabilities (keyboard, screen readers) |
| Bundle size | Size of shipped JavaScript |
| Lazy loading | Loading code/assets only when needed |
| Design system | Shared set of components, tokens, and guidelines |
| Pixel-perfect | Matches the design exactly |
| Cross-browser | Works on Chrome, Safari, Firefox, Edge |
| Core Web Vitals | LCP, INP, CLS — Google's performance metrics |

## How it's said
- "The component re-renders unnecessarily; I'll memoize it."
- "This isn't matching the Figma — spacing is off by 8px."
- "Bundle size increased by 40 KB after adding the chart library."
- "Can we get design sign-off on the mobile view?"
